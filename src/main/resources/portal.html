AIOPE Gateway — Complete Manual

Overview

AIOPE Gateway is an OpenAI-compatible LLM proxy that routes requests to multiple upstream providers. It runs as a single JAR or Docker container, exposes a web admin portal, and is designed for zero-config deployment on a Raspberry Pi or any Linux host.

API Endpoints

GET /healthServer status, provider count, blocked state. No auth required.
GET /v1/modelsList enabled providers as OpenAI-format models.
POST /v1/chat/completionsChat proxy. Supports streaming (SSE) and non-streaming. Model: provider/model-slug.
GET /api/statsUptime, requests, errors, CPU temp, load, RAM, disk, JVM heap.
GET /api/networkHostname, interfaces, IPs, MACs, DNS, gateway.
PUT /api/network/hostname{"hostname":"name"}
PUT /api/network/dns{"servers":["8.8.8.8","1.1.1.1"]}
GET /api/wifiWiFi devices and active connections.
GET /api/wifi/scanScan networks. Returns SSID, signal, security.
POST /api/wifi/connect{"ssid":"name","password":"pass"}
POST /api/wifi/disconnect{"device":"wlan0"}
POST /api/wifi/forget{"name":"MyNetwork"}
GET /api/wifi/savedList saved WiFi connections.
GET /api/configGateway config and provider list.
PUT /api/config{"apiKey":"new-key"}
GET /api/config/providersList all providers.
POST /api/config/providers{"name":"my-provider"}
PUT /api/config/providers/:name{"apiKey":"...","model":"...","apiBase":"...","path":"...","enabled":true}
DELETE /api/config/providers/:nameRemove provider.
POST /api/config/loadmodels{"provider":"name"} — fetch model list from upstream.
GET /api/certsList certs with expiry, issuer, fingerprint, status.

POST /api/certs/issue{"domain":"*.example.com","method":"dns-porkbun","credentials":"/path/creds.ini"}

Authentication

All endpoints except /health require auth via:
Header: Authorization: Bearer YOUR_API_KEY
Or session cookie (set after portal login).
Default key: aiope-gateway-key — change immediately.

Provider Configuration

Name — unique ID. API Base — upstream URL. Path — endpoint (default /chat/completions, change to /audio/speech, /embeddings, etc.). Model — model ID for upstream. API Key — upstream auth. Enabled — on/off toggle.

Clients request: provider-name/model-slug. Gateway resolves and forwards.

TLS / Wildcard Certificates

Challenge methods: Standalone (port 80), Webroot, DNS-Cloudflare, DNS-Route53, DNS-Google, DNS-DigitalOcean, DNS-Porkbun, DNS-Manual.

For wildcards (*.example.com), use any DNS method. Both *.domain and domain are requested automatically.

Credential file formats:

# Cloudflare (/opt/gateway/data/cloudflare.ini)
dns_cloudflare_api_token = YOUR_TOKEN

# Porkbun (/opt/gateway/data/porkbun.ini)
dns_porkbun_key = pk1_xxx
dns_porkbun_secret = sk1_xxx

# DigitalOcean (/opt/gateway/data/do.ini)
dns_digitalocean_token = YOUR_TOKEN

# Google Cloud: use service account JSON file
# Route53: uses AWS env vars or instance role

Create these files in the Files section. Set chmod to 600.

WiFi

Requires NetworkManager on host. Scan, connect (with password prompt), disconnect, forget saved networks. Uses nmcli.

File Manager

Sandboxed to: /opt/gateway/data, /etc/letsencrypt, /etc, /home, /tmp. Browse, edit, create, upload (50MB max), download, delete.

Deployment

# Docker
docker run -d --network host -v data:/opt/gateway/data aiope-gateway

# Bare JAR
java -Xmx256m -jar gateway-server-all.jar 8082 ./data

# Pi flash
sudo ./deploy/flash.sh /dev/sdX

Ports

8082 — Gateway + Portal. 7681 — Web Shell. 80 — Standalone cert issuance (temporary).

Environment Variables

GATEWAY_PORT (8082), TTYD_PORT (7681), DATA_DIR (/opt/gateway/data)

Pre-configured Providers

Pollinations (free, no key), GitHub Models (free tier), Google AI Studio (free tier), Cloudflare Workers AI (free tier), OpenRouter (free models), Cohere (free tier), Cline (free), Zen/OpenCode (free), Bedrock Mantle (free proxy).

Client Examples

# curl
curl http://GATEWAY:8082/v1/chat/completions \
  -H "Authorization: Bearer KEY" -H "Content-Type: application/json" \
  -d '{"model":"pollinations/openai-fast","messages":[{"role":"user","content":"hi"}]}'

# Python
from openai import OpenAI
c = OpenAI(base_url="http://GATEWAY:8082/v1", api_key="KEY")
print(c.chat.completions.create(model="pollinations/openai-fast",
  messages=[{"role":"user","content":"hi"}]).choices[0].message.content)

Troubleshooting

  • 503 blocked — click Start in top bar.
  • 401 — check API key or re-login.
  • 404 no provider — use provider/model format. Check /v1/models.
  • 429 rate limited — 120 requests/min per IP. Wait and retry.
  • 429 too many failed attempts — 10 failed logins in 15min blocks the IP. Wait 15 minutes.
  • WiFi errors — needs NetworkManager on host, --network host.
  • Cert fails — port 80 open (standalone) or valid credentials (DNS).
  • File access denied — only sandboxed paths allowed.

Multi-User Authentication

The gateway supports multiple users, each with their own API key. Admin manages users from the portal.

  • Admin — uses the gateway API key. Full access to all settings, users, and providers.
  • Users — created by admin. Each gets a unique API key. Can make API requests. Cannot manage settings.
  • Users are stored in data/users.json.
  • Users can optionally be restricted to specific providers via the providers field.
  • Both admin and user keys work as Bearer tokens and as portal login passwords.

API:

GET /api/usersList users (admin only). Keys are truncated.
POST /api/users{"name":"bob"} — creates user, returns generated API key.
DELETE /api/users/:nameDelete user.

API Key Rotation

Click "Rotate Key" in Server Info to generate a new gateway API key. The old key immediately stops working. The new key is shown once — save it. All existing sessions are invalidated.

Rate Limiting

Liberal rate limiting to prevent DoS attacks. 120 requests per minute per IP address on API endpoints (/v1/*). Returns HTTP 429 when exceeded. Portal and config endpoints are not rate-limited.

Brute Force Protection

10 failed login attempts from the same IP within 15 minutes blocks that IP from the login page. Returns HTTP 429. The block expires automatically after 15 minutes. API key auth is also protected.

Request History

The last 500 API requests are tracked in memory with: timestamp, endpoint, HTTP status, latency (ms), and user. Visible in the portal and via API.

GET /api/history?limit=50Recent requests. Color-coded: green (2xx), orange (4xx), red (5xx).

Audit Log

Tracks security-relevant actions: login, login_failed, user_add, user_delete, webhook_update, backup_export, backup_import. Last 1000 entries kept in memory.

GET /api/auditRecent audit entries with user, action, detail, timestamp.

Webhooks

Set a webhook URL to receive notifications. Supports Slack, Discord, or any HTTP endpoint that accepts JSON POST. Events are sent as:

{"event":"test","message":"...","ts":1234567890}
GET /api/webhooksGet current webhook URL.
PUT /api/webhooks{"url":"https://hooks.slack.com/..."}
POST /api/webhooksSend test notification.

Backup & Restore

Export the entire data/ directory (config, users, webhooks) as a tar.gz file. Import restores it and reloads all configuration.

GET /api/backup/exportDownload backup as tar.gz.
POST /api/backup/importUpload tar.gz to restore. Reloads config, users, webhooks.

PWA / Add to Home Screen

The portal includes a web app manifest. On mobile browsers, use "Add to Home Screen" to install it as a standalone app with no browser chrome.

Theme

Click the Theme button in the top bar to toggle between dark and light mode. Preference is saved in localStorage.

Systemd Service (Bare Metal)

For non-Docker installs, copy the service file and enable it:

sudo cp deploy/aiope-gateway.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now aiope-gateway
